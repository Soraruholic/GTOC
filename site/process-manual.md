## 2. 搭第一条产线

在一块空地执行 `/ocplant place`。命令从玩家前方固定 Z+3 的位置开始，沿 **世界坐标 +X** 放置 8 个设备方块，不根据玩家朝向旋转；需要一排 8 个空气方块。选平整地面，保留周围操作空间。

| 方块字母 | 功能 | 操作要点 |
|---|---|---|
| C | 控制器 | 右键打开控制面板；点击“加入一块煤”从背包消耗一块，获得 200,000 J 教学热量 |
| F | 计量进料口 | GT 流体管接任意面；只接受无 NBT 的 `aceticacid`、GT Ethanol 对应的 `bioethanol`、`water` |
| R | 反应釜 | 右键查看最近一次反应的入口/出口及 0–600 模型秒组分曲线 |
| D | 间歇蒸馏与冷凝 | 右键查看蒸馏入口、馏出物和釜底；可执行蒸馏工序 |
| W | 水洗与分相 | 右键查看最近一洗的入口、有机相、水相；可继续或追加水洗 |
| A | 干燥 | 右键查看入口、干燥出口和吸附水；安装芯、执行干燥 |
| P | 成品 | 右键查看产品组成；“取出全部成品”生成一个样品；空库存明确显示为空 |
| T | 残余与废液 | 右键显示待分配釜底、下一批回流和废液；选择 0/50/100% 回收或取出废液 |

- [ ] 8 种字母/颜色可辨认；中文物品名没有乱码。当前设备外观是实验标识，未做工业多方块模型。
- [ ] 执行 `/ocplant kit` 得到开发用催化芯和 4 枚干燥芯。
- [ ] 右键 R 或 C，点击“安装催化芯”；兼容命令 `/ocplant catalyst`。
- [ ] 右键 A，点击“安装干燥芯”；兼容命令 `/ocplant cartridge`。先只装一枚，便于观察容量。

### 2.1 每台机器面板怎么读

右键八种方块均打开各自的 GUI，顶栏显示本机状态；可以切换“组分库存 / 反应曲线 / 工序记录”。底部给出下一步指引和操作反馈。没有执行条件的按钮会变灰，鼠标悬停可读具体原因。Esc 关闭窗口后可查看背包。没有机器物品槽，耗材按钮从玩家背包扣除，外部流体仍从 F 接口进入。

计算期间继续接收已提交状态，面板不会因 PROCESS_PENDING 拒绝读取；修改按钮暂时禁用。普通右键和 Shift 空手右键都只开面板，不再意外推进一步。放置外接罐/管仍按第 3 节 Shift + 方块操作。

R 默认打开曲线页，四条线分别表示乙酸、乙醇、乙酸乙酯、水；水在反应段是副产物。横轴为模型时间，纵轴可切换 mol / 摩尔分数 x，悬停查看采样数值。**没有釜体积模型，因此不把 mol 曲线称为 mol/L 浓度。** 采样来自本批积分的 61 个点，显示最近一次成功反应的轨迹，非逐帧现实时间动画。默认等摩尔、无回流批次中，乙酸与乙醇的 mol 相等、酯与水的 mol 相等，因此两对曲线重合；悬停可分别读出四个数，重合不是缺少组分。

旧 0.3.0 已完成批次没有保存轨迹，升级后显示“尚无反应轨迹”；其库存和原工序记录仍保留。跑一个新批次的反应后才有真实曲线。D/W/A 的入口、出口与旁路量显示最近已提交工序；R 的“当前中间料”会随后续分离工序变化，不能把它与反应出口记录混为一项。

- [ ] 右键 C/F/R/D/W/A/P/T 均打开对应面板，角色名称、状态和可用按钮正确。
- [ ] 计算期间能继续查看面板；禁用按钮悬停有原因；关闭重开后库存一致。
- [ ] 新批次反应完成后，R 显示 61 点实际计算轨迹，可切换 mol/x 并悬停读数；旧批次无轨迹时明确提示缺少记录。

## 3. 用真实 GT 物料进料

### 3.1 先确定本次怎么供料

**本手册的主路径是：用管理员命令领取三个已经定量装液、底面已设为输出的 Ender IO 储液罐，依次放到 F 上方。** 储液罐自己通过流体接口向 F 推送，所以直连时无需管道。跑通后，3.5 再插入一段真正的 GT 流体管测试连接。两条路径都不需要 EU、RF、泵覆盖板或红石信号。

原文的 250 mB 来自程序测试定量，漏写了玩家如何获取。现在可以精确复现它，不必设法从普通桶倒出四分之一桶。这里是管理员开发验收，命令生成的是 GT 注册表中的真实流体，随后经过真实储罐接口转移；**不代表已经验收原料的生存合成产线**。

在游戏聊天栏逐行执行本节命令。`@p` 在你本人执行时选中你；不要把下面命令放到远处命令方块或直接照搬到服务器控制台。每行保留原样，不要加入空格或改成长玩家名：酸、醇两条命令各 98 个字符，已控制在旧版聊天输入的 100 字符范围内。

先完成第 2 节的八设备搭建，站在 C 旁边，暂时不要执行 `run`。保留至少 6 个空背包格。使用生存模式做定量转移，避免创造模式放置后仍保留一份含料物品；管理员在生存模式仍可使用命令。下面第二行给你一把拆除空储罐用的铁镐。

```text
/gamemode 0
/give @p minecraft:iron_pickaxe 1
/ocplant map
/ocplant status
```

新产线的 `feed` 应为 `[0.0, 0.0, 0.0, 0.0]`。如果已有进料，后面的表应核对增加量；要逐字对照绝对读数，请在远离旧控制器至少 32 格的空地新建一条。命令选中附近最近的控制器，测试时始终站在目标 C 旁边。

此版本已在服务器核对：乙酸为 `aceticacid`（ID 456），GT `Materials.Ethanol` 为 `bioethanol`（ID 59），水为 `water`（ID 1）；没有 `ethylacetate` 注册项。命令使用稳定名称，不用数字流体 ID。

### 3.2 领取恰好 250 / 250 / 1,000 mB 的三个储罐

下面每条命令各给你一个普通 Ender IO 储液罐（Fluid Tank，容量 16,000 mB），里面分别已有指定数量的液体。**无需另领空罐、乙酸桶或乙醇桶。**

```text
/give @p EnderIO:blockTank 1 0 {tankContents:{FluidName:aceticacid,Amount:250},hasFaces:1,face0:2}
/give @p EnderIO:blockTank 1 0 {tankContents:{FluidName:bioethanol,Amount:250},hasFaces:1,face0:2}
/give @p EnderIO:blockTank 1 0 {tankContents:{FluidName:water,Amount:1000},hasFaces:1,face0:2}
```

在背包悬停查看内容；若物品提示未显示完整数量，可以先放在一块普通实心方块上，空手右键打开罐 GUI，将鼠标放在中央液体条上查看。该版本罐 GUI 的容量单位可能显示为 mB；GT 面板里的 L 是它自己的流体计数显示。这里的 250 / 1,000 均指 Forge 的整数流体量。

命令已设置底面为 **Push（推）**、默认忽略红石；其余面保持默认。这些面按世界方向保存，和玩家朝向无关。不要在验收中把它改成 Pull（拉），也不要打开销毁模式。把罐放在普通实心方块上时，底面没有可接收流体的设备，因此不会自行漏掉内容。

这里有一个容易混淆的 NBT 区别：`tankContents` 是储罐物品保存液体种类和数量的字段，它是正常容器数据。本命令没有给液体增加 `Tag`，因此不会触发 OC 的“拒绝带 NBT 流体”。不要自行加上 `Tag:{}`，即使空的流体标签也会被拒绝。

- [ ] 领取并核对三个罐：乙酸 250 mB、乙醇 250 mB、水 1,000 mB。不是三个空罐，也不是甲醇或甲酸。

### 3.3 直接进料：一次只放一个罐

假设 C 的方块坐标是 `(x,y,z)`，则 F 是 `(x+1,y,z)`。**储罐放在 F 的正上方 `(x+1,y+1,z)`**；不要放到 C 或 R 上面。坐标是相对 C 的说明，不是要你输入的命令。

1. 手持乙酸罐，按住 Shift，对准 F 的顶面右键放置。Shift 是为了放方块，避免触发 OC 方块自身的右键交互。
2. 放开 Shift，等待 2–5 秒。空手右键罐，查看中央液体条：应变为空 / 0 mB。储罐每次最多推送 100 mB，末次可以只推 50 mB，不要求凑整桶。
3. 关闭 GUI，在 C 旁执行 `/ocplant status`，按下表核对乙酸增加量。
4. **只有确认罐为 0 mB 后**，用铁镐左键挖掉这个外接罐，捡起空罐。不要挖 F，也不要把含料的罐丢掉。
5. 用相同方法放乙醇罐，检查空罐和读数，再拆掉空罐。
6. 最后放水罐，检查 0 mB 和最终读数。供料完成后也可以拆掉空罐。若 5 秒后仍有液体，先按 3.8 排查，不要重复领取、重复放料。

### 3.4 逐步读数与通过条件

`feed` 固定顺序为 **乙酸 / 乙醇 / 乙酸乙酯 / 水，单位 mol**。尚未运行批次、开始时 feed 全为零时，应得到：

| 完成的动作 | 源罐剩余 | 乙酸 mol | 乙醇 mol | 乙酸乙酯 mol | 水 mol |
|---|---|---|---|---|---|
| 放空 250 mB 乙酸罐 | 0 mB | 4.34873400 | 0 | 0 | 0 |
| 再放空 250 mB 乙醇罐 | 0 mB | 4.34873400 | 4.26023759 | 0 | 0 |
| 再放空 1,000 mB 水罐 | 0 mB | 4.34873400 | 4.26023759 | 0 | 55.34468518 |

浮点累加末位可能不同，误差在 0.000001 mol 内即可。换算约定为 1 mB = 1 mL，使用标称 25 °C 密度与摩尔质量：每 mB 乙酸为 0.0173949359854 mol，乙醇为 0.0170409503773 mol，水为 0.0553446851784 mol。GT 本身不承诺真实体积单位，这是 OC 的桥接约定。

三种料合计约 63.953657 mol，低于共用的 **128 mol 进料上限**。每批只取 1 mol 新乙酸与 1 mol 新乙醇，多余进料留在 F；不是把三个罐全部一口气倒进反应釜。`getTankInfo` 的三个分量共用这份剩余容量，不能相加。

- [ ] 三次转移后，分别确认源罐为 0 mB，feed 达到对应读数。完成这一项表示储罐直连进料已通过。

### 3.5 获取并验收真正的 GT 管道

直连通过后，在同一产线上额外用 **100 mB 水** 做管道测试；这会增加进料库存，不改变第 4 节单批默认计算结果。先拆掉 F 上方的空罐。

以下命令给出一段 **GT 不锈钢流体管（普通尺寸）**、一把普通模式的 GT 钢扳手，以及一只底面输出的 100 mB 水罐。扳手的耐久 NBT 是本次开发工具的设定。

```text
/give @p gregtech:gt.blockmachines 1 5142
/give @p gregtech:gt.metatool.01 1 16 {GT.ToolStats:{PrimaryMaterial:Steel,MaxDamage:25600L}}
/give @p EnderIO:blockTank 1 0 {tankContents:{FluidName:water,Amount:100},hasFaces:1,face0:2}
```

| 部件 | 放置坐标 | 必须检查 |
|---|---|---|
| F 进料口 | `(x+1,y,z)` | 完整八设备中的第二块 |
| GT 不锈钢流体管 | `(x+1,y+1,z)` | 下端连 F，上端连储罐，无覆盖板、无输入禁用 |
| 100 mB 水罐 | `(x+1,y+2,z)` | 底面 Push，罐中确实有 100 mB 水 |

1. 将副手清空，手持管道，Shift + 右键 F 的顶面，把管放在 F 上面。GT 放管时会尝试连接它所贴的面，因此先放管，再放罐。
2. 此时管道顶面还露着。手持上述 GT 扳手，**不按 Shift**，对准管道顶面中央右键一次，以打开上端连接。该版本 GT6 风格连接允许提前接向空气。看到“已连接 / Connected”就停止；再次点同一面会断开。如果本地设置已自动接好，不要反复切换。
3. Shift + 右键管道顶面，把水罐放到管道上方。底面 Push 会把液体送入管道，管道再送到 F。当前不需要另加泵或电源。
4. 若放罐后仍未连通，手持扳手看管道侧面的连接网格：点击侧面上边缘中央对应 UP，点击下边缘中央对应 DOWN。只修复未连接的上下两端，**不按 Shift**；Shift + 扳手在此管道上切换的是输入禁用，容易把通路关掉。
5. 等待 5 秒以上，确认储罐为 0 mB，`feed` 的水比测试前增加 **5.53446852 mol**。若接在 3.4 之后，水应约为 **60.87915370 mol**。罐空而 feed 未达到该值时，液体可能还在管内；继续检查连接，不能把“罐空了”单独视为通过。

本段只有一个源、一个管、一个接收口且没有旁路。在 feed 增加量已等于全部 100 mB 的换算量时，源罐与管道应均已排空。不要在管中仍有液体时拆管或切换不同原料。核算应始终满足：**源罐减少量 = OC 增加量折算为 mB + 管内增加量**。

需要单独确认三种原料都能走 GT 管道时，在一条新空产线上按本小节搭好管道，再把 3.2 的三个罐依次放在管道上方；每种液体都等到 feed 达到 3.4 的读数后才换下一罐。此时不再重复做直连，也不加额外 100 mB 水。

- [ ] 实际放置了一段 GT 不锈钢流体管，确认上下端连接；100 mB 水完整进入 OC，水增加约 5.53446852 mol。这一项才是客户端真实 GT 管道验收。

### 3.6 不用预装罐时，容器应放在哪里

如果已有游戏内制造的乙酸/乙醇流体单元或水桶，可以使用一个空的 Ender IO 罐。此方式便于后续生存玩法验证，**不要求为本次 250 mB 基线再做一遍**。

```text
/give @p EnderIO:blockTank 1 0 {hasFaces:1,face0:2}
/give @p minecraft:water_bucket 1
```

先将空罐放到普通实心方块上，右键打开 GUI；把盛满的流体容器放到 **左上格（倒出容器）**，等约 1–2 秒，取走 **左下格的空容器**，查看中央罐量。右上格是给空容器灌液的入口，不要放错。确认数量后搬到 F 上方或管道上方；Ender IO 罐的物品形态保留内容与面配置，放下后再次核对。

普通水桶是 1,000 mB；从 NEI 领取单元时先读它实际标注的容量，不能把一个普通满单元当成 250 mB。若选用三种各 1,000 mB 的简化实验，在新空产线上最终 feed 应约为 `[17.39493599, 17.04095038, 0, 55.34468518]`，合计 89.780572 mol，也在容量内。该做法与 250 / 250 / 1,000 基线二选一。

### 3.7 拒绝与满槽：用独立空产线测试

这些项目与正常批次分开做。到离旧 C 至少 32 格的空地，新建八设备；不需要装催化芯或加热，始终站在新 C 附近。以下罐都直接放在新 F 顶面，避免把管内缓存误判为 OC 吸收。每步都先记下 status；拒绝项完成后用铁镐取回那个含料罐并保留。

不支持流体：领取 100 mB 岩浆罐，放在 F 上方等待 5 秒。应仍为 100 mB，feed 全零。这是小量、封闭的储罐测试，不是倒出岩浆方块。

```text
/give @p EnderIO:blockTank 1 0 {tankContents:{FluidName:lava,Amount:100},hasFaces:1,face0:2}
```

带标签的流体：领取以下特意带空 `Tag` 的 1 mB 水罐。应仍为 1 mB，feed 全零。这里刻意制造的是液体自己的标签；普通 3.2 的储罐内容记录不等于这种标签。

```text
/give @p EnderIO:blockTank 1 0 {tankContents:{FluidName:water,Amount:1,Tag:{}},hasFaces:1,face0:2}
```

容量：取回拒绝测试罐，确认该新产线仍完全空。领取 **2,500 mB 水罐**，直接放到 F 上方。应吸收 **2,312 mB**，feed 的水约 **127.95691213 mol**，源罐剩 **188 mB**，等待后保持不变。剩余空间不足 1 mB 水时就停止，因此不要求数字正好显示 128 mol。

```text
/give @p EnderIO:blockTank 1 0 {tankContents:{FluidName:water,Amount:2500},hasFaces:1,face0:2}
```

还要确认“满槽时管道停输”，可用另一条空产线，把同样的 2,500 mB 水罐接到 3.5 的单管上。OC 仍只能接收 2,312 mB；剩余 **188 mB 是源罐与管内合计**，不保证全留在源罐。停止后继续等 5 秒，OC 数值不得增加，不能只按源罐读数判丢料。

- [ ] 不支持的岩浆和带流体 Tag 的水都留在各自源罐，OC feed 不变。
- [ ] 独立空产线的 2,500 mB 水直连测试得到 OC 2,312 mB 等效量、源罐 188 mB；可选管道容量测试将管内残留一起核算。

## 4. 跑通一个批次

### 4.1 本次正常操作只做什么

**准备好进料与耗材 → 右键 C 点击“自动运行本批” → 面板显示本批已完成 → 右键 P 点击“取出全部成品”。** 下文的 run/status/bottle 仍作为兼容命令，按钮与命令二选一，不重复启动。 正常运行不会自动把物品送进玩家背包。只要给成品留一个空格，不需要故意填满背包；那是第 5 节可选的失败保护测试。

站在自己的 C 附近，保持同一高度、距离 12 格以内；整个批次留在旁边。确认八块设备完整、第 3 节进料已完成，且已安装一枚催化芯和至少一枚干燥芯、给 C 加过一块煤。暂不拆设备、离开区块或更改设置。

执行下面命令检查开机前状态：

```text
/ocplant status
```

应看到 `READY`、`Catalyst=true`、`dry mol=0.1`（首次只装一枚）、`heat=200000 J`（首次只加一块煤），以及第 3 节的 feed 数量。背包中 **36 个主物品格（含快捷栏）至少留一个完全空格**；装备栏和副手不算。一个没叠满但已经放了物品的格子也不算空格。

### 4.2 启动、等待、判断完成

在 C 面板点击一次“自动运行本批”，或执行一次兼容命令：

```text
/ocplant run
```

命令会提交当前阶段，并自动接着计算后续阶段，直到本批 `FINISHED` 或出现具体错误。默认包括反应、蒸馏、8 次水洗和干燥，共 **11 次阶段计算**。它只自动跑完当前一批，不会把剩余进料反复加工成很多批。

**先等 5 秒，再执行 status。** 这是便于操作的检查间隔，并非程序规定必须等满 5 秒。新版 status 和机器面板在忙碌期间也可读取最近已提交状态；看到 PENDING 时隔 5 秒再查，不要连续重复 run。修改请求才会返回 PROCESS_PENDING。面板每 5 个服务器 tick 刷新，显示本机忙碌状态，但没有虚构百分比或 600 秒倒计时。面板内可以直接看到完成状态。

```text
/ocplant status
```

首次、默认参数、无回流的批次，完成时应看到 `OC FINISHED`、`wash=8/8`、`ester` 约 **96.244%**。在取出前，`product` 应约为 `[0.00307143, 0.01243282, 0.22019269, 0.0]` mol，顺序仍为酸 / 醇 / 酯 / 水。水为零是本次理想选择性干燥模型的输出，不表示现实干燥必然没有残水。

**判断完成以 FINISHED 和成品读数为准，不要求在聊天中看见每个中间阶段。** 自动模式可能很快跨过它们；需要逐阶段学习时用 4.5 的 `step`。概要 `ester=EMPTY` 表示尚无成品，反应釜的产物请看 R 的出口记录或曲线。

如果 status 能正常显示，却停在 `READY`、`REACTED`、`WASHING` 或 `WASHED`，阅读最后的状态文本。例如 `HEATER_EMPTY` 是缺热、`WASH_WATER_LOW` 是缺洗水、`OFF_SPEC` 是未达质量门；这种情况等待更久不会自行解决，按第 5 节补足条件后再执行一次 `run`。

若连续约 **30 秒**面板仍显示计算中且阶段不前进，记录命令、时间和实际返回内容，交给维护者检查工作队列、服务器 tick 与日志。30 秒是人工排查阈值，不是代码已有的超时；现版没有玩家可用的取消/加速命令。不要通过反复执行 run 或拆控制器尝试加速。

- [ ] 执行一次 run 后，通过 status 看到 FINISHED、wash=8/8，且默认成品约为 0.22019 mol 乙酸乙酯、96.24 wt%。没有要求捕捉所有中间阶段。
- [ ] 单批仅使用 1 mol 新乙酸、1 mol 新乙醇和约 4.72857 mol 洗水；剩余 feed 保留，运行期间背包没有自动新增成品物品。

### 4.3 到底要等多久，能不能加速

| 时间或操作 | 现版实际含义 |
|---|---|
| 反应的 600 s | 模型积分覆盖的化学反应时间；计算 2,400 个 0.25 s 步长。玩家不用等待现实 600 秒 |
| 整条产线的时间 | 还包括蒸馏、分相、干燥的计算；这些单元尚未实现由设备处理速度决定的游戏倒计时，不能把 600 s 当作整厂现实加工时长 |
| 本机纯引擎计时 | 历史 0.3.0 版本：2026-10-03，在服务器主机上，用该版 JAR、Java 17、默认进料独立跑三次：0.106 / 0.062 / 0.059 秒。没有读写玩家世界；不是 0.3.1 界面响应测速 |
| 玩家实际等待 | 还需游戏 tick 提交、共享工作队列、网络延迟；上面的数字不含这些。当前没有完整客户端端到端计时，按“等 5 秒后查 status”操作 |
| 加速 | 当前引擎已经尽快完成计算，没有速率倍率命令、升级槽或人为 600 秒等待可跳过。run 自动走完后续阶段，step 则每次只走一个阶段 |
| 多加煤或多装芯 | 增加可用热量或除水容量，不会加速计算。改温度、压力或洗涤次数会改变工艺结果，不等于加速播放 |

独立计时只验证计算开销及默认结果一致性，不代替实机运行时间验收。计时原始记录随网页发布在 `data/process-timing.json`。当前单工作线程为所有产线服务，同时运行多条产线可能排队。

### 4.4 bottle 是“取出全部成品”，不是启动生产

`bottle` 的用途是：**把目前 P 成品库存中的全部混合物转移到背包中的一个“OC 产线定量样品”物品里，保留每种组分的 mol 数。** 名字叫样品，但现版不是抽取少量 aliquot，也不是每 mol 生成一瓶。

先在 P 面板或 status 记录 product 数值。确认至少有一个空背包格后，点击 P 的“取出全部成品”，或执行兼容命令：

```text
/ocplant bottle
```

本版不要求你先拿空玻璃瓶，不消耗原版瓶子；命令会创建一个不可堆叠的分析容器物品。其瓶子外观仅用于表达容器，尚未实现按 250 mB / 1,000 mB 分装、纯 GT 流体输出或将这个样品再次倒回设备。因此本次用它带走和查看成品，不把它当作可直接接入其他 GT 配方的纯乙酸乙酯桶。

打开背包，把鼠标放在新样品上，应能看到乙酸、乙醇、酯、水各自的数量，以及 `Ester: 96.244 wt%` 左右的质量分数。默认会有酸与醇杂质，这是成品组成的一部分。

再次执行 status：`product` 应变为全零，阶段仍为 `FINISHED`；剩余 feed 与 waste 没有被这次取出清空。新版概要会显示 `ester=EMPTY`，P 面板显示“成品库存为空”；不再把空库存显示为 0% 纯度。产品只在明确执行 bottle 时进入背包；一次调用只放入一个物品、占一个空格。

```text
/ocplant status
```

如需检查重复请求，可再执行一次 bottle：应返回 `OC refused: STREAM_EMPTY`，背包不新增第二份同样产品。这是因为第一次已经取走全部库存。若有多个批次累积在 P 中，一次 bottle 会一起取出这些库存，仍是一个带总量的物品。

- [ ] bottle 前记录 product；取出后背包增加一个带组成的样品，P 的 product 全零，样品组分与取出前一致。
- [ ] 可选重复请求：再次 bottle 返回 STREAM_EMPTY，没有复制成品。

### 4.5 想看中间过程时，用 step 分步学习

在一条新 READY 产线上，可以用下面命令代替 run。每次提交后等计算完成，再查 status；`step` 不是加速键。

```text
/ocplant step
```

| 默认新批次中累计 step 次数 | 完成后的阶段 | 意义 |
|---|---|---|
| 1 | REACTED | 模型已计算 600 s 的反应，查看 vessel 的混合物 |
| 2 | DISTILLED | 蒸馏/冷凝计算完成，分出釜底与馏出物流 |
| 3–9 | WASHING，wash=1/8 至 7/8 | 每次只完成一轮水洗 |
| 10 | WASHED，wash=8/8 | 八轮水洗完成，等待干燥和质量门 |
| 11 | FINISHED | 干燥与质量门通过，可用 bottle 取出 |

每次都等上次结束后再操作。中途执行一次 run，会从当前已完成阶段自动跑完剩余步骤。煤、原料不足时仍会停止。FINISHED 后再次 run 不会开启下一批，而是返回批次已完成的错误。

第一次验收做到拿到样品即可。继续第二批时，右键 T 选择“釜底回收 50%”（或按目标选择 0/100%），再右键 C 点击“准备下一批”返回 READY，检查洗水、干燥容量、热量，再点击“自动运行本批”。兼容命令顺序是 recycle 0.5 → next → run。**next 只准备下一批，不会自行启动。** 有回流时组成已改变，不再逐字套用第一批的 96.24% 基准。

## 5. 故障、残余与重启

### 5.1 可选：故意填满背包，检查取出保护

这是人为制造“没有空位”的测试，**不是生产会自动填满背包**。第一次只想跑通批次，可以跳过本小节。如果要测，必须在某批 FINISHED 后、尚未执行 bottle、product 仍非零时做；已经取空后再测只会得到 STREAM_EMPTY。

1. 先用 status 记录非零 product，保留截图或抄下数值。
2. 将泥土等普通物品拆成小堆，手动占满全部 36 个主背包格（含快捷栏）。每格有一个物品即可，不需要每格 64 个，不需要占满装备栏或副手。不要复制含料样品来填格。
3. 执行 bottle，应返回 `PLAYER_INVENTORY_FULL`；再用 status 确认 product 与之前相同。程序先查空格，失败时不会把产品消耗掉或丢在地上。
4. 把一格普通物品放入箱子，使该格完全空出；再执行 bottle，应只获得一个样品，product 变为零。此时这批产品已取出，不要再把第 4 节当成另一份产品重复领取。

- [ ] 可选满背包测试：非零产品在拒绝时保持不变；腾出一个完全空格后成功取出一份。

### 5.2 可选：权限检查

有第二位管理员时，让其靠近你的产线执行 status 或 run，应得到 OWNER_REQUIRED；普通玩家当前没有使用这些开发命令的权限。你自己移到目标 C 12 格以外、附近没有其他 C 时应被拒绝；回到原 C 旁继续。无需为了正常运行创建第二个账号。

- [ ] 可选权限检查：其他玩家不能操作自己的产线；远离后拒绝，回到附近可继续。

### 5.3 其余故障、残余与重启

| 场景 | 操作 | 预期与恢复 |
|---|---|---|
| 缺催化剂 | 新建产线，跳过安装芯 | `CATALYST_REQUIRED`；原料不扣减 |
| 缺热 | 新建产线，不加煤后 step | `HEATER_EMPTY`；本阶段不提交，加煤后重试 |
| 缺水 | 只供酸/醇，运行至洗涤 | `WASH_WATER_LOW`；补水后 run 继续 |
| 干燥容量不足 | 少装芯或连续跑多批 | `OFF_SPEC` 保留湿料；补芯再 run；若洗涤不足，`extra-wash` 后再 run |
| 减少洗涤 | READY 时 `settings 345 80000 6` | 可能不达 95 wt%，不能把不合格料当成成品 |
| 残余回流 | FINISHED 后 `recycle 0.5` | 50% 釜底的四组分一起回流，另一半进入废液 |
| 下一批 | 路由釜底后执行 `next`，核对原料/洗水/干燥容量/热量，再 run | next 只将阶段设回 READY；回流中的水/酯会一起进釜，影响反应 |
| 废液取出 | 执行 `waste` | 得到保留四组分的废液容器；不是删除按钮 |
| 正常重启 | 记下 status，退出并请维护者正常停服/启服 | 已提交阶段恢复；未完成的后台步骤放弃，重进后手动 run |
| 卸载区块 | 运行/完成后离开远处，再返回 | 已提交库存保留；未完成步骤不保证自动继续 |

含料设备在生存模式下阻止正常挖掘。创造模式强拆、编辑 NBT、跨存储系统突然断电，仍可能绕过原版世界/玩家存档的保存边界；这版 **没有** 宣称跨 GT 管道、玩家背包与世界存档具备 M2 级原子提交。不要以破坏正式存档的方式补测。

### 5.4 FINISHED、空成品与 STREAM_EMPTY 怎么判断

产品取走后，FINISHED 仍表示“本批结束”，不会自动开始新批次。旧版曾把空库存写成 ester=0.000%，又让重复 run 留下 BATCH_FINISHED，容易误以为没有反应；新版 P 会写明库存为空，并禁用重复取出按钮。先查看背包中的“OC 产线定量样品”，再去 T 分配釜底、C 准备下一批、A 补芯、C 启动。不要把瓶子放回 F；当前不支持回注这种产线样品。
