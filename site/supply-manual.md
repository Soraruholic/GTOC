# C6 原生供应与串联产线：可执行验收手册

**当前版本 0.4.0-va-darzens-alpha1。请用 Darzens 隔离实例；新 C14/C6 双支线按 [最新手册](darzens-manual.html) 操作。下方较早版本与基线属于历史记录。**

当前客户端版本 **0.4.0-va-dosing-alpha1**，GTNH 2.9.0-beta-2，Java 17–25。使用 Prism **GTNH-OC 0.4.0 Dosing (isolated test)**；本机隧道连接 `127.0.0.1:25566`。本次原生进料来自真实 GT 标准流体单元，C14、强碱和其他辅料仍使用开发夹具。

本手册数量表保留固定辅料基线；新增“按进料配辅料”模式及其 **0.164434 mol** 全反式晶体基线，见 [D24 工场与操作步骤](dosing-lab.html)。两种模式不能在同一已开始批次中切换。

## 1. 本轮具体要验证什么

丙酮、甲醛、乙炔各 1 个标准单元，实际扣除并返还空壳，经六台 C6 设备生产 Z-C6，再接入原有二十台设备，得到教学维生素 A 乙酸酯晶体。C6 碳源不再直接由夹具生成。

本版明确规定：**1,000 mB 注册物料 = 1 教学 mol**。这是独立游戏计量规则，不是物理体积或密度换算；GT 流体默认密度也不作为现实数据。甲醛按该注册物的单一组分教学表示，不当作现实甲醛水溶液。

`/ocsupply status` 核对当前版本和账本状态。数量写入需要短暂等待；所有设备 UI 都显示已确认状态。

## 2. 如何得到三个正确的原料单元

先输入 `/ocsupply cells`，读取当前运行时登记的三种物品及其注册名/metadata，避免用相似名称替代。

本版服务器实测登记：丙酮单元 `gregtech:gt.metaitem.01:30672`，甲醛单元 `miscutils:Formaldehyde:0`，乙炔单元 `gregtech:gt.metaitem.01:30781`。末尾数字为 metadata；优先使用下列专用命令，避免手写普通 `/give` 时弄错格式。

管理员快速验收可直接执行：

```text
/ocsupply givefeed acetone
/ocsupply givefeed fluid.formaldehyde
/ocsupply givefeed acetylene
```

每条命令给 1 个**真实注册的 GT 流体单元物品**；之后仍会实际消费。命令只是测试时省去生存生产，不证明上游配方已在生存模式全部跑过。背包不足时拒绝，不向地面丢料。

生存生产依据如下；用 NEI 查看最终单元的生产/装填配方及准确机器界面：

| 物料 | 已审计的原生配方示例 |
|---|---|
| 丙酮 `acetone` | 流体加热机：1000 mB 乙酸钙溶液 → 1000 mB 丙酮，80 tick，30 EU/t；另有木醋液蒸馏和异丙苯路线 |
| 甲醛 `fluid.formaldehyde` | GT++ 化工厂：甲醇与氧气各 32000 mB，甲醛催化剂、电路 21 → 32000 mB 甲醛；1800 tick、120 EU/t、外壳等级 1 |
| 乙炔 `acetylene` | 化学反应器：3 份电石粉、2000 mB 水、电路 1 → 1000 mB 乙炔、5 份氢氧化钙粉；300 tick、480 EU/t |

此表确认配方登记，未替代矿物生成、催化剂制作、科技解锁和全部上游成本验收。**首次快速验收推荐使用上面的三个 givefeed 命令**，把机器与化学链先跑通。

## 3. 放置并绑定四个工段

总计 26 台。每条命令均从当前位置南侧第三格起沿东向放置；每次换一排平地，留出至少三格南北间距。保持所有关联机器在已加载区块。

1. `/occouple place`，记录偶联 UUID，暂时不投其自带 C6 夹具。
2. `/ocva place`，记录乙酰化 UUID，保持空线。
3. `/occhain place <偶联UUID> <乙酰化UUID>`，创建六台后段。
4. `/ocsupply place <偶联UUID>`，创建六台 C6 上游。

UUID 用命令真实返回值替换，不保留尖括号。后两条命令各要求准确的绑定对象；每条偶联线只能绑定一个 C6 供应源。`/ocsupply status` 可找回自己的 UUID、阶段和坐标。

## 4. 三次原生投料：不用桶、管道或瓶子

到 C6 第 0 台“原生单元进料站”：

1. 将丙酮单元拆成 **恰好 1 个**，放入快捷栏并手持。
2. 右键机器，点击 **导入手持原生单元**，等待确认；所选快捷栏槽变为空壳，库存增加丙酮 1 mol。
3. 关闭界面，换成恰好 1 个甲醛单元，再打开并导入。
4. 同样导入乙炔；乙炔显示在气体库存。

满背包可正常替换原槽，不要求额外空格。一次不消费整叠；手持 2 个以上、容量不符、未知流体、通用储罐或带流体 NBT 的混合物会拒绝。此版本未接入管道或通用容器。

三种原料各限一次。如果已导入或有待恢复请求，同种原料不会再次扣除。正常投料后“全线 / 诊断”显示 C6 原生碳源 3/3。

## 5. 六台上游设备及操作顺序

从西向东：

| 编号 | 设备 | 操作 |
|---|---|---|
| 0 | 原生单元进料站 | 三次导入；然后一次“装载辅助夹具” |
| 1 | 羟醛 / 脱水釜 | “羟醛加成”→“脱水并分配 MVK” |
| 2 | 乙炔化 / 后处理釜 | “乙炔化 / 水解净工序” |
| 3 | C6 烯丙基重排釜 | “烯丙基重排净工序” |
| 4 | Z-C6 分离 / 交接 | “分配 Z-C6”→“交接 C6 / C14夹具” |
| 5 | 残余 / 废液 / 气体 | 查看自缩合物、1,4 加成物、E-C6、氨和残余 |

辅助夹具投放 NaNH₂ 1 mol、NaOH 0.02 mol、H₂SO₄ 0.01 mol、水共 3 mol；强碱与水分开记账。乙炔活化先于水解，未使用的氨基钠也在水解时消耗，全部氮计入 1 mol 氨。工序包含理想分配，不声称仅靠一个真实过滤器就能完成纯化。

每一步等待账本提交即可，没有另设真实反应等待时间。轨迹横轴为工序，数量为 mol。整条上游通常以操作和数次写盘为主，不需要等待游戏几小时。

默认每种原生原料 1 mol：

| 羟醛加成形成 4-羟基丁-2-酮 | 0.855 |

| 乙炔化总消耗 | 0.678699 |
| 1,2 加成形成 C6 叔醇 | 0.64476405 |

交接后第 4 台 Z-C6 清空；偶联第 0 台出现相同数量。C14、格氏试剂、乙醚和后处理辅料按这个 C6 数量比例投放，明确继续标记为夹具。

## 7. 接着跑原有二十台设备

偶联线已经 LOADED，从 **C6 入活化釜** 开始：

`第0台入釜 → 第1台双活化 → 第2台收乙烷 → 第3台合并 → 第4台偶联 → 第5台酸性后处理 → 第2台再收乙烷 → 第5台教学分离`

本条供应输出的 C6 已按理想分配与干燥表示，偶联第 0 台没有新增水，无需强行点击干燥。不要装载旧的“痕量水夹具”，因为已有真实上游物料。

然后按 [后段串联手册第 4–7 节](chain-manual.html) 依次装辅料、接收 C20、选择性加氢、过滤、交接乙酰化、运行 3600 模型秒、分离并交回后段、净重排、结晶。乙酰化保持 303 K；自动本批在正常 20 TPS 下约 12–15 秒加提交等待。

本批最终全反式晶体约 **0.04986177530 mol**，指定单 Z 晶体约 **0.00013850493 mol**。数量明显低于旧 1 mol C6 夹具基线，因为上游存在分配损失，且旧后段辅料仍按固定量投放，乙酰化相对过量会进一步改变分布。晶体仍留在后段第 4 台库存，无 GT 成品物品导出。

## 8. 关闭窗口、重连与不确定提交

进料先落盘意图，再消费单元并保存玩家数据，最后给 OC 记料。已保存的单元消耗带凭证，重复点击不再扣第二次。

- 消费前关闭窗口、移动距离或换手持槽：不消费，意图可能留在 PENDING。把原单元放回原槽，站在第 0 台八格内，明确执行 `/ocsupply retry <供应线UUID>`。
- 单元已经变为空壳，但 OC 尚未入料：打开第 0 台点击 **恢复已保存进料**，根据已保存凭证补记一次。
- 无持久凭证且原槽内容也不匹配：继续隔离，不自动退款或造料。管理员保留报告及玩家/世界备份进行核对。

`retry` 只消费记录中的原槽、相同物品状态；已有持久凭证时转为恢复记账。它不会绕过缺料条件。本协议处理正常保存与进程中断；只恢复玩家文件或只恢复 OC 账本的任意历史备份不在保证范围内，回滚应使用同一完整世界备份。

## 9. 集中客户端与重启验收

人工检查六台上游右键能否打开；不同 GUI 缩放下中文、按钮、库存翻页、三组工序曲线是否清楚。分别查看液体、气体和固体，确认单元消耗后为空壳。

测试满背包时先留手持槽为单个原料，成功后原槽直接替换为空壳。测试拒绝时使用两枚堆叠或其他流体，确认数量与物品都不变。三次进料后重复同种原料也应拒绝。

重连后 `/ocsupply status` 找回原线，检查三项 nativeFeed、阶段及余料。缺少方块引用可由管理员 `/ocsupply repair <UUID>` 恢复原空位，不重新生成物料。账本升级至 v2.4，降级必须用匹配完整备份，不能只换旧 JAR。

## 10. 自动证据与仍未完成的范围

`/ocsupply qa` 是管理员使用的保留区 Forge 验收，实际消费已注册单元物品、保存合成玩家消耗凭证，并运行到最终晶体；它不证明用户客户端渲染或生存取得过程。`/ocsupply report` 导出全账本，包含原生请求和 C6 交接。

当前每世界最多 4 条供应线、4 条后段线，自动 QA 各占一条；旧历史 QA 也占已有后段配额。请勿反复新建大量试验线。正常测试应复用已放置的线继续操作。

本轮尚未完成：完整原生生存供应、C14/β-紫罗兰酮支线、强碱/溶剂/催化剂成本闭环、连续多批、工业参数、真实分離相平衡、全路线独立化学审核和 E03 微观机理。C6 重排页面提供的是待审阅候选解释，不是实验证明的唯一路径。
