PLAY / NATIVE CARBON TO PRODUCT

从原生碳源，
跑通一批维生素 A。

适用模组 0.4.1-process-contract-alpha1，GTNH 2.9.0-beta-2，Prism 实例 GTNH-OC 0.4.1 Process Contract (isolated test)。这是管理员测试流程。新线共 48 台设备，其中上游 16 台；每台右键打开状态界面。

碳骨架主线已经闭合：原生碳源 → 柠檬醛 → 假紫罗兰酮 → β 骨架 → C14/C6 → 成品封装。NaNH₂、催化剂、部分溶剂和后段辅料仍显式使用夹具；转化/分配为未标定教学参数。成品是 OC 账本库存及其引用，还不能投入 GT 配方。
建线原料上游操作后段集中验收查看物料可视化

先建立六个相互绑定的工段

选择平坦空地，每排之间至少隔三格；命令在玩家南侧三格生成东西向一排设备。每次执行后等待账本空闲，记下返回 UUID。所有关联设备必须在已加载范围内，不能重叠。

  1. /occouple place：8 台偶联设备，记录偶联 UUID。
  2. 向南移至少三格，/ocva place：6 台乙酰化设备，记录乙酰化 UUID。
  3. 再向南移至少三格，/occhain place <偶联UUID> <乙酰化UUID>：6 台后段设备。
  4. 再向南移至少三格，/ocsupply place <偶联UUID>：6 台 C6 设备，记录 C6 UUID。
  5. 再向南移至少三格，/ocdarzens place <C6 UUID>：6 台 C14 设备，记录 C14 UUID。
  6. 再向南移至少三格，/occampaign place-ionone <C14 UUID>：16 台上游设备。绑定时全部关联线必须为空。

每排从西到东编号从 0 开始。查看 /occampaign status；丢失设备引用时只在原位执行 /occampaign repair <上游UUID>。旧六机/十二机线仍用原模型，不能在旧批次直接追加新步骤。

若测试服提示产线上限，请使用已有的新线或另开独立测试世界；不要删除旧账本或旧世界来腾出名额。模组为每类产线保留有限容量。

25 件上游物料，加 3 件 C6 碳源

背包空出至少 25 格，执行 /occampaign ionone-kit。它给予真实 GT 注册物品，尚未写入 OC 反应库存。每次拆出恰好一件，快捷栏手持 → 右键上游 0 号接收机 → “导入手持原生物料” → 等待确认 → 关闭界面换下一件。单元的空壳回到原槽，粉末消耗后槽清空。

1000 mB 标准单元或一整份粉末 = 1 教学 mol。这不是密度、酸浓度或气体状态换算。桶、管道、通用流体容器、小份/微量粉末、改名物品和带额外 NBT 的物料不接受；不能向方块倾倒进料。接收机的“液流”只是账本分类，不说明氢气或粉末真实物态。

C6 另外需要三件：依次执行 /ocsupply givefeed acetone、/ocsupply givefeed fluid.formaldehyde、/ocsupply givefeed acetylene，每件手持一份导入 C6 的 0 号接收机。先导完原料再开始反应。可以自行制作同一注册身份的物品替代管理员命令。

按这个顺序操作上游，最后才交接 C14

右键界面显示角色、阶段、mol 库存、已提交工序曲线和拒绝原因。大部分步骤提交一次净工序；点击后等服务器确认即可，没有现实化学倒计时。曲线横轴为提交工序，纵轴为本工段 mol，不是浓度或秒。被拒绝时悬停按钮读原因，不要用夹具补齐缺料。

资格检查到底认证了什么？

新身份 beta-ionone-unresolved 定义 β 连接骨架；α 使用独立身份 alpha-ionone-unresolved。E/Z、新手性中心保持未定。旧 beta-ionone 的明确 E 结构不被覆盖。新版 C14 模型专门接受未定 β，不能把旧 E 库存或 α 库存冒充进去。

本版教学门槛：β 摩尔分数至少 0.98；水、各酸/碱残余不超过 β 的 0.001 倍；资格池仅允许 β、α、假紫罗兰酮和水。95% 纯组分分出是假设的选择器，所以能得到纯教学 β 池；这不是现实蒸馏/萃取已经可行，也不是 E-β 产品证书。

U07 的 0.01 mol 强酸强碱中和单独列出 573 J 稀水溶液参考放热。实际物流并非该稀溶液标准域，因此不据此求温升、冷却负荷或 EU；U06 弱酸、U08 二元酸和其他反应热仍未知。

接通 C6、C14、偶联与成品后段

  1. C6：三件原料导完后，依次运行辅助夹具 → 羟醛加成 → 脱水 → 乙炔化后处理 → 烯丙基重排 → Z-C6 分离。不要点击旧的“C14 夹具交接”。
  2. C14：收到实际 β 后已为 LOADED，不装旧夹具。依次 Darzens → 皂化 → 酸化/中和 → 脱羧 → 共轭化 → 分配 C14 → C14/C6 联合交接。为满足接口精度，交付量向下取 12 位小数，尾数留在 C14 罐。
  3. 偶联：0 号“C6 入活化釜” → 1 号“双活化” → 2 号“收集乙烷” → 3 号“合并偶联进料” → 4 号“偶联 95% 进度” → 5 号“酸性后处理” → 2 号再收乙烷 → 5 号“教学分离”。
  4. 后段：0 号“按进料配辅料” → 接收 C20；1 号选择性部分加氢；2 号过滤、交接乙酰化。后段配料仍是显式夹具来源。
  5. 乙酰化：0 号计量入釜；1 号自动本批，速度选 300 模型秒，目标 3600 模型秒。实际通常几十秒到几分钟，取决于服务器及落盘；可暂停，不能跳过保存。REACTED 后出釜、过滤、分离中间料。不要装载乙酰化自己的旧夹具或包装中间料。
  6. 结晶：回后段 3 号接收单乙酸酯 → 脱水重排净工序；4 号结晶分配 / 质检。参考批全反式库存约 0.02589196025 mol，单 Z 约 0.00007192211 mol；这来自后段教学分配，不是对未定进料做了真实 E/Z 测定。

局部按钮位置可查 C14 手册、C6 手册、乙酰化手册。局部旧夹具投料量不适用于这条新线。

封装、领取，再在原设备开第二批

背包留至少一空格，在后段 4 号点“封装成品流”，或靠近设备执行 /occampaign pack <串联UUID>。整股库存转到唯一产品容器，因此原罐变空。查询 /occampaign status 找到封装 UUID，然后 /occampaign claim <封装UUID> 领取引用凭证；手持右键查来源与数量。无需 bottle，也无需装满背包。

满背包只用于故障测试：封装前满则拒绝封装；领取前满则保留产品拒绝领取。重复 claim、复制纸张、丢弃纸张都不会复制或删除物料。丢失凭证可重领。产品仍为 OC 引用物品，没有 GT 消耗接口。

封装完后，在后段 0 号“归档并开下一批”，或 /occampaign next <串联UUID>。旧批所有残余、母液、气体、催化剂、产品与回执完整保留；新批回到空/进料阶段，重新导入 25+3 件并重复以上顺序。归档不是实际清洗；最多保存 16 份，达到上限会拒绝而非删除旧料。

一次集中完成真人客户端验收

服务端合成玩家可检验容器、真实物料与落盘；真人还需要检查画面、按钮文字、鼠标提示和重连体验。记录每次操作前后的阶段、mol、产品 UUID 与提示，不用每开发一个小步骤就重跑整套。
