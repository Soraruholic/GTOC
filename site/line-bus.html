水相废液

来源：盐水、洗涤水、酸碱残余

分开水相收集；分析盐、溶剂和金属后决定处理。不能按 pH 合格就排放。

COLLECT_ONLY

有机母液

来源：醇、酯、溶剂、异构体混合物

按相容性 / 批次保留；分离回收需有模型与质量凭证，残液仍有容器。

RECOVERY_REVIEW

反应性残余

来源：格氏试剂、强碱、含活性金属物料

在设备旁受控失活 / 淬灭，确认后才能向中央处理交接；没有适配器则就地暂停。

LOCAL_REQUIRED

尾气

来源：氨、酸性气体、未知气相

先就地控制与捕集，不共用一根混合尾气管。吸收液、尾气和排污都有有限去向。

LOCAL_REQUIRED

催化剂 / 滤饼

来源：金属、载体、夹带母液

密闭分类收集；可能自燃或有反应性者就地封存，回收前保留负载与夹带账。

LOCAL_REQUIRED

未知 / 不合格物料

来源：缺组成、缺身份、缺来源

同相态专用隔离仓；隔离不是中和或销毁；满仓向上游背压。

QUARANTINE

回收的三个门槛

收集并不等于回收。① 组成 / 相容性确认 → ② 有模型的分离或处理，计入能耗、药剂、夹带和残液 → ③ 回收物流重新获得用途资格。当前代码落实有限收集、隔离、背压和待回收状态；未知分离效率、未知处理反应及热负荷不自动补数。

BUILD IN MATERIAL ORDER

先准备去向，再引入原料。

01

选择产品与模型

乙酸乙酯先走八机基础教程；维生素 A 按 C5 → C14 / C6 → 偶联后段学习。多方块布局是另一种实现层，不能和旧命令混读。

02

留出仓储、管廊与检修道

源罐按物料分组，产品和废物分区；本轮总线测试架沿 +X 每隔 2 格、沿 +Z 每隔 3 格布置，右键可读。

03

先接废物与局部安全单元

未知液 / 固体隔离、反应性残余就地封存、尾气局部处理。确认接收容量，绝不设置无容器的出口。

04

集中补料、逐路计量

只向 SOURCE 存储端口送入过滤器允许的真实 GT 流体 / 催化芯。总线调度到对应 FEED_BUFFER，缺料只阻塞该路线。

05

沿反应与分离操作

每站阅读输入、机理、条件、等待与产物检查；当前总线缓冲尚未统一接到所有化学设备，按现有步骤显式操作。

06

验收来源与第二批

核对产品、母液、废物和残余总账。回收物通过资格门后才能返回进料；重启和重复请求不应增加库存。

RECOVERY STARTS WITH ACCOUNTING

回用候选和排污：两股都保留杂质。

已实现中央混合物流分流。它按操作员给出的同一比例分配每个组分，不是蒸馏、萃取或净化：80% 分流不会把 90% 纯度变成 100%。回用候选进入专用待检仓，排污进入有限废物仓；两个出口任一被占用或容量不足，整次操作拒绝，入口不扣料。反应性残余、未知料和成品待检通道不接受此操作。

去向目标组分杂质用途资格

一键建架同时生成 recovery-reuse 和 recovery-purge 两个实体存储端口。分流与原料调度共用单写入器、持久化回执和真实玩家身份；inspect 报告保留输入组成、出口组成、源仓 revision、来源记录、比例与 request UUID。热负荷仍为 unknown，不自动换算 EU；候选流没有返回 SOURCE 的路线。

/ocfactory recover <factory UUID> organic 80 <request UUID>
/ocfactory recover <factory UUID> residue 80 <request UUID>

乙酸乙酯选择 organic，维生素 A 选择 residue；每次新操作用一个 UUID，重复验证保留原 UUID。空仓返回 RECOVERY_EMPTY。当前化学设备输出适配尚未接完，切勿为了演示给真实仓伪造废液；/ocfactory selftest 会在完全隔离的账本里覆盖带杂质分流、容量拒绝、局部安全、重复请求和落盘恢复。

MATCH THE COMMAND TO THE WORLD

一键测试架，实际怎样排？

下图按服务器 LineBus.position 的同一规则绘制：一格高的存储端口，X 方向间隔 2 格，Z 方向间隔 3 格。编号与确定的节点顺序一致；不是整厂反应器的多方块预览。拖动旋转、点选端口，或用下拉框和按钮。

SOURCE 是外部真实物料入口；FEED_BUFFER 是计量缓冲；LOCAL_BUFFER 是工艺适配边界；CENTRAL_HOLD 是分类集中接收。当前节点之间由账本事务转料，图中不画尚未实装的原生物理管。

EXECUTABLE INTEGRATION RACK

一条命令，构建总线测试架。

使用本轮 line-bus 构建的管理员客户端，在空场地执行下面一条命令；两条任选其一。命令建实际存储端口并启用调度，不领取原料，不替代整厂化学设备。

/ocfactory integration ester
/ocfactory integration vitamin_a
  1. 预留玩家东侧 X+2…X+16、南侧 Z+3…Z+18、高度与玩家脚下相同的空场地。已有方块拒绝覆盖。
  2. 等待账本提交后出现存储架；同一玩家、同一产品重复构建返回同一 factory。旧库存保留。
  3. 先检查 MISSING_FEED。右键任一端口读取节点、进料状态和收集状态。液 / 气 / 固体各有身份过滤。
  4. 连接已经有物料的 GT / EnderIO 储罐向 SOURCE 输入；等待自动送到 FEED_BUFFER。CHARGED 只表示首批缓冲备好，不表示反应已完成。
  5. 报告在世界目录 oc-factory-tests/ 下；隔离模型测试使用 testFixture=true，productionInventory=false。它不会给玩家或生产账本增加测试物料。
  6. 记录 factory UUID；重登 / 卸载再加载 / 重启后核对原量。已放置的端口被拆除会停运，不会自动复制方块。
/ocfactory diagnose <factory UUID>
/ocfactory inspect <factory UUID>

inspect 导出当前真实节点、容量、路由与来源记录；自检报告单独列出持久化故障恢复结果。真人需补查 UI 可读性、储罐方向、外部管道和多人操作。
