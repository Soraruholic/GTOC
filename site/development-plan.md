# GTNH-OC 可执行开发计划

规划基准：2026-10-02；目标整合包 `GT_New_Horizons_2.9.0-beta-2_Java_17-25`。

## 1. 交付定位与已验证起点

本项目有两个独立交付物：**Minecraft 模组**负责服务器权威物料与玩法；**HTML 教学文档站**负责结构观察、机理解释、练习与开发文档，可离线使用或托管在 GitHub Pages。网页不是游戏嵌入界面，不要求 Chromium/CEF，也不连接游戏服务器。

此前原型已完成正版进入、虚拟实验台启停/温度/催化剂/反向批次、原子选择和初步机理卡片；历史基线 `0.2.0-alpha1` 加入 CDK 2.9 结构身份、20 个物种世界字典、revision 网络包和旧状态隔离。暂停批次的保存、正常 stop 与重启恢复已实测。化学内核自检包含 36 条轨迹、360000 次推进；NBT、网络和会话单元测试通过；服务器内部 FakePlayer 并发、真实区块卸载/重载和 13 个部分 tick 保存恢复也通过。这些证据不等于两个真人客户端压力测试。

alpha1 历史基线 SHA256：`7db52b295908a4df7d34a9087739cf8a5662402008e6b1cac5030b693952defd`。该阶段本地、Prism 与服务器哈希一致；服务端运行 Java 17。JDK 探针结果与对应 hash 保存在 `data/jdk-matrix.json`；这是历史启动探针，不能代表当前构建的长时压力与所有第三方模组兼容性。当前游戏 JAR 与证据见第 6 节 N4–N6。

**研究构建进展：** `0.2.0-alpha2-dev` 的精确存档与持久化事务核心已完成独立测试，五个实际进程中断点通过，详见第 6 节。此为历史独立研究证据；当前双端已升级 `0.2.0-alpha2-m2-dev`。N4/N5 与 N6 生命周期、容量/上限、重复请求和同版本重启已实测，M2 样品库存原型 gate 通过；完整边界见第 6 节。

**仍未完成：**真实 GT 库存桥接、通用反应图规则、定量物性与热力学、工业设备、AI 推理。游戏样品混合物已具有精确持久事务；尚无与虚拟反应台或 GT 流体的物料互转。网页 Wiki 已接入 20 个结构条目、1 个固定教学反应及完整七状态机理课、4 类设备档案和 2 个分子的离线轨道观察；这些网页内容不会自动解锁游戏生产能力。

## 2. 范围与发布定义

| 交付 | 用户可做什么 | 不应宣称什么 |
|---|---|---|
| 独立文档站 1.1 | 手册、20 条目 Wiki、五种 3D 分子、七状态 Fischer 三维/电子记账课、两种有边界的反应器课、HOMO/LUMO cube、练习、笔记、估时和研究来源 | 三维是分子动力学、轨道图给出能垒/产率、网页功能已进游戏 |
| 0.2 playable | 真实进料→规则域内反应→取样/分析→库存核验；审核标准物料才可通过出口 | 任意底物的真实速率，混合液直接变纯品 |
| 0.3 process alpha | 有参数域的连续釜、换热、闪蒸/分相、有限精馏、回流与排污 | 任意四组分、任何工况皆准确 |
| AI 可选支线 | 提议新候选、帮助作者审核和补内容 | 模型分数等于物理产率，AI 可以直接生成库存 |

首个反应族限于 CHO 饱和单官能团羧酸/一级醇酯化与水解；多官能团、芳香、强位阻、复杂立体和聚合另立评估。参数不足时交付定性探索；不得把游戏调参标作真实动力学。

## 3. 工期、资源与依赖

M0–M5 合计 **52 工程日**；M6 再加 **24 日**；M7 可选 **15 日**。按每周 5 日、25% 集成余量，分别约 **13 周到 0.2**、**19 周到 0.3 alpha**；同一工程师串行做 AI 再加 3.75 周。M6 后广泛小范围发布准备另需 7–10 工程日（未计入前述 76 日）。每周只能投入 2 日时，0.2 约 32.5 周。

这是任务拆解估计，不是历史实测或固定日期承诺。假设一名熟悉 Java/Forge 的工程师，并有每周 2–4 小时的有机化学/化工审核。数据等待、库冲突和重大研究失败可能另增工期。单人不能同时计入并行收益。

关键链：M0 → M1 → M2 → M3 → M4 → M5 → M6。M4 的绘制可在 M1 后试做，但完整反馈依赖 M3；M7 依赖 M3 评估集，不阻塞主线。

## 4. 逐阶段工作与验收

### M0 · 收紧已经跑通的原型

**4 工程日；版本 0.1.1-dev；依赖 现有 0.1.0-dev。**

交付：冻结客户端/服务端 JAR 与配置清单；拆出无 MC 依赖的计算接口；开发世界备份/恢复脚本；演示参数迁入带单位及来源的内容文件。

- 保留 org.gtnhoc.chem 的算法回归，记录构建 JDK、字节码、实际运行 JDK。
- 把 v1 演示批次保留为独立类型，损坏时重置只适用于虚拟教学；生产批次必须隔离恢复，不能重生物料。
- 补两玩家冲突、区块卸载、运行中保存恢复；100 个实验台做基线测量。

**验收：** 现有单玩家验收可复现；两个玩家并发操作无异常；备份恢复成功；吞吐和 tick 开销有测量值。

**停止/降级：** 若恢复会复制或抹去库存，暂停新增设备，先修状态机。

**证据：** JAR 哈希、环境锁、集成日志、性能基线、存档恢复录制。

### M1 · 让分子拥有可靠身份

**8 工程日；版本 0.2.0-alpha1；依赖 M0。**

交付：ChemToolkit 适配器；SpeciesDefinition、世界物种字典及版本化结构 ID；CDK 2.9 最小模块试验。

- 定义同位素/立体/电荷/显隐式氢/芳香性/盐/互变异构体标准化策略；atom-map 不参与全局物种身份。
- 只做 SMILES 解析、SMARTS 子图匹配、分子式和二维坐标；不假定 CDK 提供通用反应执行器。
- 20 个结构黄金样例，含乙醇/二甲醚、质子化、立体未指定与指定；检查库许可、service loader 和专服无客户端类。

**验收：** 全部身份案例通过，异构体不碰撞，NBT 往返不变；目标客户端/Java 17 专服真实加载；测量依赖体积与启动增量。

**停止/降级：** 两天集成试验后仍有无法隔离的依赖冲突，缩减模块或比较 OpenChemLib；不把整套化学库直接塞进 mod。

**证据：** 规范化文档、黄金结构集、依赖树及 notices、样品只读查看器截图。

### M2 · 先保证每一滴物料的账

**8 工程日；版本 0.2.0-alpha2；依赖 M1。**

交付：Immutable BatchState、密封样品瓶、专用槽与转移事务；版本迁移和恢复机制。

- 记录 mol、J、相库存、batchId、revision；摩尔分数由库存推导，温度由有来源的物性关系计算。
- reserve → validate → commit；主线程修改 World/TileEntity；后台仅处理快照。
- 模拟 1000 次分合、微量残余、满输出、断电、重复事务和旧 revision；暂不开放 AE2 或普通混合物流体管。

**验收：** 随机分合与存档恢复保持物料账；同一事务重放不重复提交；超大/NaN/负量输入被拒绝；缺热物性返回 unsupported。

**停止/降级：** 任何增殖回路、事务重放增量或静默丢料都阻塞后续 GT 输出。

**证据：** 转移协议、误差/残余政策、性质测试、崩溃恢复日志与游戏取样演示。

### M3 · 可泛化但有边界的反应族

**12 工程日；版本 0.2.0-alpha3；依赖 M1 + M2。**

交付：ReactionRule + 受约束图编辑器；首个酯化/水解可逆族；Python 独立数值参考。

- 先覆盖 CHO 饱和单官能团羧酸/一级醇；明确排除芳香、强位阻、多反应位点和未处理立体语义。
- 规则包含角色、映射、断成键、氢/电荷账、副产物、适用域、参数来源及版本；RDKit 离线交叉验证。
- 建立 40 例审核集：20 个支持域组合，含至少 5 个未逐条预登记组合；20 个缺角色/越域/条件反例。
- 分开 candidate、qualitative_supported、quantitative_validated、unsupported；有结构候选但缺速率时不输出物理产率。

**验收：** 原子/氢/电荷闭合；未枚举组合得到正确新酯；反例无误转化；已给定玩具网络与独立求解器一致，缩步收敛。

**停止/降级：** 公开动力学数据不足时仍可交付定性探索；不得标成专业预测。

**证据：** 物种/规则/参数清单、适用域说明、反例与参考曲线、每项来源。

### M4 · 把观察变成可操作的推理

**8 工程日；版本 0.2.0-alpha4；依赖 M1；完整反馈依赖 M3。**

交付：ModularUI2 二维结构 widget、稳定 atom-map、机理步骤编辑与逐项反馈。

- 画出键级、楔线、电荷、孤对电子、显式氢；结构变更时缓存布局，帧内只渲染。
- 箭头从电子来源出发，协同步骤一次提交多箭头；教学验证成功不修改生产库存。
- 完成一套人工审核的酯化机理；网页三维作辅助教材，游戏内三维与 Chromium 嵌入后置。
- 两种 GUI 缩放、中文/英文、Angelica、客户端关闭界面后的 GL 状态做检查。

**验收：** 原子跨步骤对应稳定；错误箭头得到具体原因；净机理与总计量一致；截图无遮挡和明显跳位。

**停止/降级：** 缺机理证据只显示候选；不由 RXNMapper 的原子映射编造中间体。

**证据：** 可操作录制、渲染矩阵、教学用例与误操作反馈表。

### M5 · 第一条真正接入 GT 的物料流程

**12 工程日；版本 0.2.0-playable；依赖 M2 + M3 + M4。**

交付：GTMaterialBridge、计量入口、间歇釜、取样/分析、质量门与有限标准产品出口；NEI/BQ 最小引导。

- 先运行时导出 Materials/FluidRegistry 全注册表，确认乙酸乙酯是否已有 ID；首批桥接 10–20 种结构明确的物料。
- 固定 mB↔mol 与 EU↔J 的游戏约定，枚举所有可逆桥接回路；禁止通过容器编辑生成物质。
- 对齐 5.09.54.20 的 MTEEnhancedMultiBlockBase / ProcessingLogic 生命周期；检查 MetaTileEntity ID 冲突。
- 第一轮交付进料→反应→取样→库存核验；仅为参数已验证的标准物料开放输出，未纯化混合物留在样品中。

**验收：** 真实 GT 库存贯穿流程；满输出/断电/卸载/重启不增殖；残留物没有被质量门删除；未审核新酯只保留为可分析样品。

**停止/降级：** 没验证分离不承诺高纯成品；检测到与旧配方组合刷料则关停该桥接边。

**证据：** 双端 JAR、材料映射表、循环增殖审计、独立世界完整流程录制。

### M6 · 连续反应与可验证的分离

**24 工程日；版本 0.3.0-process-alpha；依赖 M5 + 数据包通过审核。**

交付：先 CSTR/换热，再闪蒸/分相，最后有限精馏与回收排污；独立物性/流程参考。

- CSTR 明确物料、能量、液位、滞留和进出流；EU、模拟时间倍率与冷却一致；先不引入传质限制。
- 为乙酸/乙醇/乙酸乙酯/水搜集有有效域的纯物性及二元参数；选择 thermo 或 DWSIM 离线对照。
- 用至少 20 个工况验证相态、分配、回收及热负荷；非理想/共沸/液液分相必须显式建模。
- 没有数据则退回经标记的理想体系教学支线；固定床/PFR、流化床和聚合分布留待后续。

**验收：** 流入/流出/库存和能量闭合；冷却故障、回流及排污产生可解释响应；域内误差按参考数据不确定性设阈值并记录。

**停止/降级：** 找不到可靠二元/动力学数据时，不做四组分定量精馏承诺；先发布守恒的流程模型。

**证据：** 版本化参数包、相图/闪蒸对照、工况误差表、产线验收与负载测试。

### M7 · AI 先证明价值，再进入玩法

**15 工程日；版本 可选研究支线；依赖 M3 的评估集与校验接口；不阻塞 M5。**

交付：一个正向模型的可复现只读推理服务，及独立 FlowER 可行性报告。

- 优先固定 Molecular Transformer 或 AiZynthModels 的一个正向版本，记录代码、权重 SHA256、数据与模型许可。
- 建立 200 例项目评估集：80 正例、40 条件/无反应对照、40 越域、20 结构语义、20 非法输入；无反应标签需有证据。
- 与规则基线比较有效新增候选、误报、拒答、条件敏感性、时延/显存和审核成本。FlowER 先核对机器 GPU，25 GB 只是研究时官方要求线索。
- 服务只返回候选；幂等任务、快照 hash、seed、超时/断线回退；结果不能直接兑换游戏库存。

**验收：** 所有进入生产的反应仍须完整物料验证及参数审核。建议研究支线门槛：审核有效覆盖新增≥10个百分点、支持域误报≤5%，并报告区间；数字是拟定门槛。

**停止/降级：** 收益不足、硬件/许可不合适、条件外推不可靠，则保留作者辅助工具，默认玩法不依赖 AI。

**证据：** 冻结模型、环境、评估集/报告、推理服务演示和成本预算。

## 5. 工程拆分与接口契约

以下是拟新增模块/包的责任划分，不代表仓库中已全部实现。先保留单仓库，业务边界稳定后再拆构建模块。

| 拟定包 / 内容 | 边界与核心接口 | 第一轮约束 |
|---|---|---|
| `chem.identity` | `ChemToolkit`、`SpeciesDefinition`、`CanonicalizationPolicy` | 冻结标准化版本；图、电荷、同位素与立体参与身份；atom-map 单独管理 |
| `chem.inventory` | 不可变 `BatchState`、`PhaseInventory`、`TransferTransaction` | mol/J 广延量；两端 revision；残余量不丢失；失败保留库存 |
| `chem.rules` | `ReactionRule.match(snapshot)`、图编辑、完整计量 | 匹配不是反应发生证明；输出候选与拒绝理由 |
| `chem.solver` | `advance(snapshot, modelVersion, dt)` | 守恒、非负、误差控制；缺参返回 unsupported；保留固定种子 |
| `chem.content` | 物种/规则/物性/机理 JSON 与来源 | 参数有单位、T/P/组成有效域和许可证；审核版本与存档绑定 |
| `integration.gt` | 导入计量、桥接、标准商品质量门 | 仅白名单、原子守恒；兑换环路审计，残留不删除 |
| `client.structure` | MUI2 二维渲染/命中/箭头与反馈 | 不在每帧调用布局；线程不碰服务端世界对象 |
| `integration.predictor` | 可选候选接口、超时、缓存、幂等 | 默认只读；结果不能写生产库存；断线不影响已审核本地模型 |
| `docs/handbook` | 独立静态文档站 | 纯前端；离线自包含；Pages 只上传生成的 `site/` |

**结构数据。** 保存稳定结构 ID、标准化算法版本、canonical serialization、分子式（派生）、电荷和立体语义。不要因为 canonical SMILES 恰好相同就跨工具版本无条件合并。盐、互变异构体、未指定立体要有书面规则。世界内物种字典需要内容校验、迁移和缺失内容隔离。

**反应规则。** 一条规则至少含 `id/version`、底物角色、映射 SMARTS、图编辑、显隐式氢策略、全副产物、条件适用域、证据级别、参数引用。不能把酸当催化剂从库存账中无条件删除。原子映射可为审核工具；映射本身不能生成真实机理。

**批次数据。** 显式规定每种组分的 mol、相、广延能量 J、批次体积/压力边界和设备状态。温度须由带来源的热量关系得到；无热物性时先交付等温模型。生成能加总与显式反应热两套记账择一，避免重复记热。mB↔mol 和 EU↔J 是有版本的游戏缩放约定，不伪装成 GT 全局已有的真实 SI 定义。

**转移与保存。** 拟由主线程验证并冻结相关批次，单写入器完成持久化，再由主线程确认结果；检查双方 revision、容量和事务 ID。当前独立核心使用同步全快照原子替换，不能直接放入 tick；重复提交返回已有结果。分割时分割组分与能量，不复制总 mol tag。对微量残余规定归属与容差。损坏生产 NBT 进入隔离/恢复，绝不能调用虚拟实验台“补 1 mol”重置。独立核心已验证存档层的双端恢复一致性；游戏容器保管权、World/TileEntity 生命周期与异步确认仍须验证。

**计算预算。** 初期设可配置的物种数/候选数/子步数上限，例如每批 32 个物种、每次 64 个候选与 200 个子步作为起始实验值；达到上限延迟求解或返回明确状态，不能悄悄截断丢物料。所有数值上限都需负载测试后调节。主线程只调度与提交，工作线程读取不可变快照。过期结果丢弃，库存保留。

**设备次序。** M5 计量入口→间歇釜→取样分析→受审核出口；M6 连续釜/换热→闪蒸/液液分相→有限级精馏→回收/排污。使用 GT5 5.09.54.20 的实际 `MTEEnhancedMultiBlockBase` / `ProcessingLogic` 生命周期及 StructureLib，MetaTileEntity ID 集中登记。输入/输出能源与持料量都由服务器管理。NEI 展示有边界的反应族与证据，BQ 指引玩家用对照实验理解功能。

## 7. 验证、失败策略与专业引擎选型

- **身份：** 至少 20 个黄金案例，包含同分异构、电荷、氢与立体；每次内容升级做旧档迁移。
- **库存：** 至少 1000 次随机分合，覆盖满出口、微量残余、重复事务、旧 revision、非法量和异常恢复。相对与绝对容差按量纲定义，不能只有一个全局 epsilon。
- **反应：** 40 个初始正反例与域外样本；未逐条枚举的域内组合需要生成正确新产物。玩具网络与独立求解器一致不等于现实动力学已校准。
- **机理：** 原子追踪稳定、电子来源明确、协同箭头同时验证；一套人工审核 Fischer 机理先于自由编辑。网页 3D 只辅助空间观察，游戏内优先可靠 2D。
- **流程：** 至少 20 个有来源参考工况；相态、组分分配、库存和热负荷均检验。乙酸/乙醇/水/乙酸乙酯可能出现共沸和液液分相，不能仅按沸点输出纯物质。
- **性能：** 固定机器/版本/世界，报告 p50/p95/p99 与内存。100 台生产小釜新增主线程 p95 < 2 ms/tick 是待验证目标；现有虚拟实验台的短时基线见 D4，不能替代真实库存与反应求解压力。压力失败先限制并发与计算域。
- **兼容：** 两玩家、卸载重载、断电、GUI 缩放、中文/英文、Angelica；普通流体管和 AE2 在单独验收前保持不支持。

CDK 用于 Java 结构层；RDKit 用于离线模板/图编辑交叉验证。RMG 在其数据库适用域生成机制，Cantera 求解给定机制；二者不是任意液相有机反应引擎。SCINE Chemoton 适合重要小体系的离线网络探索。thermo 或 DWSIM 可作物性、闪蒸与流程参考；若与游戏实现共享同一算法和参数，仅称交叉实现校验，不称独立实验证据。

AI 先评估 Molecular Transformer 或 AiZynthModels 的固定正向版本；FlowER 单独作为电子/机理候选研究。数据、权重、代码分别核对许可和哈希。模型置信度不等于发生概率或产率，pseudo-time 不等于真实秒数。M7 门槛是研究提案，不能写成已经实现的性能。
