# 乙酰化切片：一次可以实际执行的验收

**当前版本 0.4.0-va-darzens-alpha1。请用 Darzens 隔离实例；新 C14/C6 双支线按 [最新手册](darzens-manual.html) 操作。下方较早版本与基线属于历史记录。**

版本：0.4.0-va-coupling-alpha1。适用于 GTNH 2.9.0-beta-2 / Java 17–25。旧乙酸乙酯八设备线继续使用原手册。

本手册的乙酰化工段沿用首轮模型；当前版本另外提供 [C14/C6 工段](coupling-manual.html)。

本轮终点是 hydroxenin 单乙酸酯中间料；全反式维生素 A 乙酸酯仍是后续目标。不要把本批样品当作维生素 A 成品。

## 1. 先确认客户端与服务器版本

在 Prism 选择新的隔离实例 **GTNH-OC 0.4.0 Coupling (isolated test)**，登录自己的正版账户并进入已经配置的测试服务器。本机已配置 SSH 隧道时，游戏连接地址为 `127.0.0.1:25566`；该地址仅在运行隧道的本机有效。旧实例的 OC JAR 与新服版本不相同，不能混用。本次没有代替你启动或操作 Minecraft 客户端。

管理员在聊天栏执行：

```text
/ocva status
```

应显示 0.4.0-va-coupling-alpha1、服务状态和世界事务序号。初次启动短暂 LOADING 正常；QUARANTINED 不是空库存，需要管理员查账，不能删账本重建。管理员身份沿用此前配置。

## 2. 放置六台机器

找一片平坦空地，朝向不限。站立位置南侧第三格开始、沿正 X（东）方向连续六格必须都是空气，下方最好有地面。执行：

```text
/ocva place
```

命令会返回起点坐标和产线 UUID。它不会替换已有方块；遇到“需要连续六格已加载的空位”就换一片空地再执行。放置后稍等状态提交，六台设备从西到东依次为：

| 偏移 | 面板标记 | 机器 | 主要操作 |
|---|---|---|---|
| x + 0 | F | 计量储罐 | 装载教学原料、计量入釜 |
| x + 1 | R | 夹套乙酰化釜 | 设温、推进、自动、暂停、加速、出釜过滤 |
| x + 2 | K | 过滤器 / 滤饼 | 查看固相、滤饼持液、残余 |
| x + 3 | S | 教学分离器 | 分离中间料 |
| x + 4 | P | 中间体分析 / 包装 | 质量门、包装、领取 / 补发样品引用 |
| x + 5 | W | 回收 / 废液缓冲 | 查看回收流、回收 80% 物流 |

每一台都直接右键打开 UI。只有放置者可以操作此线；F 的免费开发投料还要求管理员权限。六台都要齐全、位于已加载区块；不得把它们视为六个可随意独立搬动的空壳。本版设备不可正常挖掘，避免误操作使账本物料失去入口；没有设计生存合成配方或通用布管系统。

## 3. 本版如何获得原料

右键 F，点击 **装载教学原料**。这次投料仅允许全新空线执行一次，所有下游样品持续带有开发夹具标记。具体得到：

| 组分 | 物质的量 | 作用 |
|---|---|---|
| hydroxenin（H） | 1 mol | 待选择性乙酰化的二醇 |
| 乙酸酐 | 1.3 mol | 酰化剂 |
| 吡啶 | 0.8 mol | 教学催化介质；本模型未解算酸碱形态 |
| 对二甲苯 | 10 mol | 溶剂 |
| NaCl 形式固体 | 0.05 mol | 过滤与固体账演示示踪物；不是论文投料条件 |

此切片的 v2 机器不接收 GT 桶、单元、储罐或管道的 drain / fill。不要准备 250 mB 的旧乙酸乙酯线投料，也不要把原生水倒入新釜。注册表中存在乙酸酐不代表 hydroxenin、吡啶与对二甲苯的全线供给已经接通。关闭原生接口是本版明确的实现边界，避免把独立 GT 存档与 OC 账本错误地当成共同事务。

## 4. 计量、设温与读曲线

仍在 F 点击 **计量入釜**。F 保留 0.5% 残余，其余 99.5% 进入 R。此时 R 应有 H 0.995 mol、乙酸酐 1.2935 mol、吡啶 0.796 mol、对二甲苯 9.95 mol、NaCl 固相 0.04975 mol；温度默认 303 K。

到 R 右键，确认阶段 CHARGED。可以在反应开始前点击 **切换釜温**，按 303 → 323 → 343 → 303 K 循环；第一次验收保持 303 K。该按钮在已经开始积分后会禁用，鼠标移到禁用按钮上会给出原因。

每台 UI 有 **库存 / 品质、反应轨迹、物流 / 能量** 三页。库存超过一页时点击“翻页”；数量单位为 mol，Lq / Sol 表示液相与固相。反应轨迹显示五组分，点“mol”可换为 mol/L，浓度采用明确固定的教学体积 10 L。横轴是模型秒；移动鼠标可查看采样点。

这不是原论文的缩放复现。10 L、教学速率常数、统一热容与热浴由游戏定义，不能直接用来设计现实实验。

## 5. 跑通一个反应批次，实际要等多久

点击 **自动本批**。默认速度每次推进 300 模型秒，共需 12 次，服务每 20 tick 尝试推进一次。在正常 20 TPS、无其他账本事务排队时约需 12–15 现实秒；服务负载、落盘和区块卸载会延长时间。以界面的模型秒和阶段为准，不把这个估时当作硬性保证。

**切换加速**在每次 60 / 300 模型秒之间切换。60 模式通常需要约一分钟；两档都使用相同的 1 s 积分步长，最终物料结果应相同。**推进 60 s**只手动推进一次，不是“现实等待一分钟”。

可以点击 **暂停**，确认状态写入后观察模型秒停止；再点自动继续。单次事务进行时按钮短暂冻结，是为了避免同一库存重复写入。手动请求在主线程复核前关闭界面或离开会取消；已经落盘的请求不会被关闭界面撤销。已确认开启的自动批次在你关闭 UI 后可继续，只要整线区块仍加载。服务器重启会从最后一次持久化的模型秒继续；没有离线时间补算。

反应到 **3600 / 3600 模型秒** 后阶段应为 REACTED。303 K 参考末态如下（允许显示舍入）：

| 组分 | 反应釜中约为 / mol |
|---|---|
| H | 0.02316635 |
| M | 0.69376090 |
| D | 0.27807276 |
| 乙酸酐 | 0.04359359 |
| 乙酸 | 1.24990641 |

D 是竞争副产物，不能从质量账中消失。对二甲苯、吡啶和固体仍在库存中。这里约 30% 的二乙酰化并非来自文献拟合，不应解读为真实选择性。

## 6. 过滤、分离与包装

按顺序操作：

1. 在 R 点击 **出釜并过滤**，阶段变为 FILTERED。R 留下 0.5% 设备残余。K 保留大部分固体及 2% 液相持液；滤液进入 S。到 K 右键检查固液都在。
2. 在 S 点击 **分离中间料**，阶段变为 SEPARATED。P 得到富含 M 的中间料，W 得到回收混合物流，S 保留残余。这是逐组分教学分配器；尚不是带相平衡的萃取塔或精馏塔。
3. 在 P 看湿基质量分数和 H/M/D 池内 M 摩尔分数。教学门槛分别为 80% 和 85%；不是药典纯度，更不是“全反式维生素 A”指标。303 K 默认批次应能过门。
4. 在 P 点击 **包装中间料**。阶段 PACKAGED；P 的设备库存清空，物料转入唯一世界账本里的样品库存。界面继续显示“已包装账本样品”，不会把清空设备误报为样品丢失。
5. 腾出一个背包格，在 P 点击 **领取 / 补发样品引用**，得到一张引用纸。无需空瓶，不消耗空瓶，也没有把全部组分拆成很多瓶填满背包。纸上只有世界、产线、样品与所有者 ID，没有化学数量。

若背包已满，领取明确拒绝；样品依旧在账本。已有同一个引用时再次点击不会再占一格。丢弃或遗失引用后可以补发；复制纸也不会复制任何材料。本版样品是可查询的教学终点，暂时没有向 GT 原生物料或新批次回注样品的接口。

## 7. 回收、残余与下一批的边界

在 W 点击 **回收 80% 物流**，回收混合物进入 F，W 留下 20% 废流。F 的原始残余也仍在。不应把回收后的酸、溶剂和杂质合并为“纯溶剂”。本版只展示一次回收分配，尚未开放自动清洗和连续多批循环；不能再用“装载教学原料”给已有库存免费续料。

需要第二个独立工况时，到另一片空地执行 `/ocva place` 建立新线。本版最多 16 条线、4096 个持久化回执；这是一组明确的原型边界。到达上限后拒绝写入，不能靠删除世界账本清零。正常首轮验收只需一到三条线。

## 8. 集中手动验收清单

| 项目 | 操作 | 通过标准 |
|---|---|---|
| 六机 UI | F/R/K/S/P/W 各右键一次 | 标题、角色、数量与按钮匹配；字体和按钮没有遮挡 |
| 空相 | 新线未投料时看库存与曲线 | 清楚显示空库存，不出现 NaN 或虚构历史 |
| 权限 | 普通其他玩家尝试右键 | 不能操作他人产线 |
| 实际曲线 | 自动一批，切到反应轨迹页 | H 降低、M 先升、D 与乙酸增加；61 点轨迹来自实际积分 |
| 暂停 / 加速 | 中途暂停、恢复、切换速度 | 模型时间服从状态；最终数量不因同条件加速变化 |
| 关闭 UI | 点击前关闭、自动后关闭分别验证 | 关闭不能使已经提交的物料回滚或复制 |
| 满背包 | PACKAGED 后填满背包，再领取 | 有具体拒绝原因；样品不丢失；腾一格后成功 |
| 重复领取 | 连点、重开界面再领 | 同一引用不反复占格；账本样品只有一份 |
| 遗失引用 | 把纸放箱中或丢弃，再补发 | 可获得引用；数量仍由唯一账本控制 |
| 重启 / 卸载 | 管理员停服重启或离开区块再回来 | 从最后持久化状态恢复；残余、样品、历史不重置 |
| 可视化教学 | 浏览器切 E01/E02、选原子、回答问题 | 三维可旋转；二维和反馈准确；关闭 WebGL 仍可阅读 |

最后一列请记录“通过 / 失败 / 未测”，并附 Minecraft 截图、游戏分辨率、GUI 缩放和复现步骤。自动服务器验收不能代替你的实际客户端渲染检查。

## 9. 导出报告与排错

管理员执行：

```text
/ocva report
/ocva status
```

服务器工作目录产生 `oc-va-world-report.json`。报告包括每台设备液固组分、能量、模型时间、样品、残余、历史与事务回执。报告用于检查；它不是可直接覆盖回游戏的存档格式。

| 现象 | 含义 / 处理 |
|---|---|
| BUSY_FROZEN / SOLVING / COMMITTING | 单写入器正在处理，等待刷新；不要删文件 |
| NOT_COMMITTED_BINDING_CHANGED | 落盘前机器、区块或手动会话发生变化；本请求没有提交 |
| NOT_COMMITTED_RECOVERED | 故障后确认旧状态，重新读取界面再操作 |
| COMMITTED_RECOVERED | 提交后回执曾不确定，恢复后已确认新状态；不能再人工补料 |
| QUARANTINED | 权威文件校验、锁或恢复失败；保留文件与备份供管理员检查 |
| 按钮灰色 | 鼠标悬停读取具体理由；可能阶段、权限、整线完整性或质量门不满足 |
| 自动看似停住 | 看模型秒、TPS、区块是否加载以及有无其他事务；停止不代表正在模拟现实等待 |

如果创作模式误拆了方块，物料仍在账本：先 `/ocva status` 找到自己的线 UUID，到原坐标执行 `/ocva repair <line UUID>`。它只在原位置补回空缺绑定，遇到其他方块会拒绝，不会重建或增加物质。

新增 v2 权威文件是世界目录下 `oc-unit-v2/CURRENT.va2`。TileEntity 只保存产线绑定。旧 v1 四组分产线与 M2 样品权威仍独立，不进行无提示格式迁移。

## 10. 验收之后继续做什么

第一优先：C14 与 C6 的干燥、双活化、偶联及酸性后处理。先把水失活、乙烷气体、Mg/Br/Cl 载体与废盐纳入账本，再接入半加氢、选择性乙酰化后段和维生素 A 乙酸酯纯化。

第二优先：解决吡啶 / 溶剂 / 中间体的真实供给、GT 边界隔离缓冲和可核查的生存成本。已找到含溴矿物电解配方，但矿物获取和多方块机器门槛还需完整核实。

第三优先：独立化学审核机理、寻找可追溯的动力学与分离数据；未审核和未标定继续在 Wiki 标示。量化优化端点、中间体以及后续 TS/IRC 保持独立研究支线。
