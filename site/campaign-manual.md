# D29–D33：从真实原生物料到第二批

版本 `0.4.0-va-campaign-alpha1`。本手册对应 GTNH 2.9.0-beta-2。先用当前独立测试实例进入已升级的测试服；旧版模组会被版本握手拒绝。测试流程使用管理员权限，生存制作链不计为已验证。

## 1. 六个工段如何摆放

在平坦、已加载、上方有空间的位置建立新线；不要对已运行的旧 C14 线追加上游。每次放置后等 `/occampaign status` 或相关 status 命令显示账本空闲，再继续下一步。

1. 执行 `/occouple place`，记录返回的偶联 UUID；它生成东西向八台设备。
2. 向南移至少三格，执行 `/ocva place`，记录乙酰化 UUID；它生成东西向六台设备。
3. 再向南移至少三格，执行 `/occhain place <偶联UUID> <乙酰化UUID>`，记录串联 UUID。
4. 再向南移至少三格，执行 `/ocsupply place <偶联UUID>`，记录 C6 UUID。
5. 再向南移至少三格，执行 `/ocdarzens place <C6 UUID>`，记录 C14 UUID。此时全部关联线必须尚未投料。
6. 再向南移至少三格，执行 `/occampaign place <C14 UUID>`，记录上游 UUID。

每排从西到东为编号 0 起的机器。每台都能右键打开 UI；阅读库存、曲线和诊断，鼠标悬停在禁用按钮上可看拒绝原因。各命令将机器放在玩家位置南侧三格，因此先确认那里是空位。不要跨区块卸载操作；需要全部关联设备齐全、已加载。新线共有 38 台设备，靠近每台操作时也要确保关联排在加载范围内。

`/occampaign status` 列出你自己的上游、串联、批次和封装 ID。`/occampaign repair <上游UUID>` 只在原位恢复丢失引用，不移动设备、不产生物料。其他工段沿用各自 repair 命令。

## 2. 获取并导入 18 件上游物料

背包先空出至少 18 格，执行 `/occampaign kit`。命令先确认全部注册物料存在再给予；这是测试取得真实 GT 注册物品，不是用命令直接写入 OC 数量。也可以自行制作相同标准单元与整份粉末。

| 原生物料 | 件数 | 接受注册标识 | 本批教学当量 |
|---|---:|---|---:|
| 丙酮单元 | 1 | acetone | 1 mol |
| 乙炔单元 | 1 | acetylene | 1 mol |
| 氢气单元 | 1 | hydrogen | 1 mol |
| 氯乙酸单元 | 1 | molten.chloroaceticacid | 1 mol |
| 甲醇单元 | 4 | methanol | 4 mol |
| 水标准单元 | 4 | water | 4 mol |
| 氯化氢单元 | 2 | hydrogenchloride | 2 mol HCl 净当量 |
| 硫酸单元 | 1 | sulfuricacid | 1 mol H₂SO₄ 净当量 |
| 整份甲醇钠粉 | 2 | dustSodiumMethoxide | 2 mol |
| 整份氢氧化钠粉 | 1 | dustSodiumHydroxide | 1 mol |

操作：拆分堆叠 → 快捷栏手持恰好一件 → 右键上游 0 号原生接收机 → 点击“导入手持原生物料” → 等待账本确认 → 关闭 UI 查看空单元 / 已消耗粉末 → 换下一件。标准单元必须是 1000 mB，消费后返空壳到同一槽；粉末消耗后槽清空。粉末小份 / 微量份、桶、通用流体容器、附带 NBT 的物料及其他流体均不接受。

上限按表限制，甲醇和水各需导入四次，甲醇钠和 HCl 各两次。一次点击不需要空瓶；返空壳占原来的槽。**这里 1000 mB 或一整份粉末 = 1 教学 mol，不是现实体积、酸浓度或气体标准状态换算。** 接收缓冲中的“液流”是暂存物料账分类，不能据此推断氢气或粉末已溶解。

本接口不支持桶倾倒或管道。C5 强碱 NaNH₂ 及催化剂仍通过明确夹具提供；原生甲醇钠和 NaOH 在此供应给 C14，不冒充 C5 炔基化所需强碱。

## 3. 推进 C5 与 A01

1. 上游 0 号机点“装载强碱与催化剂夹具”，仅一次。库存增加 NaNH₂、Pd、CaCO₃、Pb，来源为夹具。
2. 上游 1 号机点“U01 乙炔化净工序”。预期 C5 炔醇 0.9 mol；未反应丙酮、乙炔保留；强碱后处理形成 NH₃ 与 NaOH。
3. 上游 2 号机点“U02 半加氢 / 过还原”。预期烯醇 0.82935 mol、过还原醇 0.02565 mol；1 号机仍有炔醇 0.045 mol。氢气按目标及过还原实际化学计量扣除。
4. 上游 3 号机点“A01 酯化 / 分离”。生成氯乙酸甲酯 0.85 mol，分配 0.833 mol 至 4 号机；水、未反应酸/甲醇及催化酸留在 3 号机。
5. 上游 4 号机点“交接 A01 与原生辅料”。酯、甲醇钠、甲醇、NaOH、水和 HCl 从真实 OC 库存扣除，按酯库存缩放后进入 C14 设备。只有 β-紫罗兰酮继续夹具生成。极小除法余量保留，不能重复交接。

C5 是后续 C8 开发的上游库存，**目前不会自动变为 β-紫罗兰酮**。酯化进度、半加氢进度与过还原比例是教学参数，没有真实停留时间、气液传质或动力学拟合。每个点击等待一次持久提交，通常秒级，以“账本处理中”消失为准，不设现实反应等待时长。

## 4. 接通 C6、C14 与后段

使用 [C14 双支线手册](darzens-manual.html) 的 C6 和后段操作，改变下面两点即可：

- C6 仍导入丙酮、甲醛、乙炔三个真实标准单元（额外于上游 18 件）。依次使用 `/ocsupply givefeed acetone`、`/ocsupply givefeed fluid.formaldehyde`、`/ocsupply givefeed acetylene`，每件手持一份导入 C6 0 号机；依次运行辅助夹具、羟醛加成、脱水、乙炔化后处理、烯丙基重排、Z-C6 分离。不要点 C6 旧“C14 夹具交接”。
- C14 **不点“装载标明来源的夹具”**，它在绑定上游后会拒绝。上游交接后 C14 已处于 LOADED；继续 Darzens → 皂化 → 酸化/中和 → 脱羧 → 共轭化 → 分配 C14 → C14/C6 联合交接。

偶联八机：0 号“C6 入活化釜” → 1 号“双活化” → 2 号“收集乙烷” → 3 号“合并偶联进料” → 4 号“偶联 95% 进度” → 5 号“酸性后处理” → 2 号再次“收集乙烷” → 5 号“教学分离”。后段 0 号机“按进料配辅料” → 接收 C20；1 号机选择性部分加氢；2 号机过滤、交接乙酰化。不要在乙酰化线装载自己的旧夹具，也不要包装中间料。

乙酰化 0 号计量入釜；1 号“自动本批”，速度选 300 模型秒，每个自动周期尝试推进一次事务，共 3600 模型秒。通常几十秒到几分钟，取决于服务器与落盘；可以暂停，不能跳过保存。REACTED 后出釜并过滤 → 分离中间料。回到后段 3 号机接收单乙酸酯 → 脱水重排净工序；4 号机结晶分配 / 质检。

## 5. 封装成品与领取凭证

后段 4 号机有“封装成品流”按钮；先空出一格背包，点击并等待确认。也可在设备附近执行 `/occampaign pack <串联UUID>`。

封装将 4 号机整股湿晶体流移动到账本产品容器，包含全反式、顺式组分和夹带液；不会凭空纯化。4 号机变空是正常结果。使用 `/occampaign status` 找到封装 UUID，再执行 `/occampaign claim <封装UUID>` 领取凭证，手持右键查询批次、来源和实际数量。

凭证不是可投入 GT 配方的维生素粉末。它引用唯一世界中的封装库存，没有在 NBT 存储可复制物质量。再次 claim 会检查背包已有凭证；如果纸张丢了可重领，物料仍只有一份。满背包会拒绝领取，已经封装的物料不会掉到地上；封装前满背包则拒绝封装。封装完成后断线，重连查询 status 并 claim 即可。

## 6. 原设备开第二批

满足结晶结束且已封装，在后段 0 号机点“归档并开下一批”，或在后段设备附近执行 `/occampaign next <串联UUID>`。等待提交，再查 status。

预期：旧批次出现在封存列表；新批次 ID 不同；原设备绑定和所有者不变；revision 递增；上游 / C6 回到 FEEDING，C14 / 偶联 / 乙酰化 / 后段回到 EMPTY。全部旧原料残余、母液、气体、滤饼、热账、成品和交接回执都保存在旧批次，不自动给第二批用。

重新领料并完整重复第 2–5 节。归档是有容量上限的虚拟封存，未建模实体清洗和废物运输；最多 16 份后停止，不删除旧库存。原始请求回执不会清掉，过期客户端 revision 也不能作用于新批。

## 7. 故障与恢复验收

| 操作 | 预期 |
|---|---|
| 连续点击同一按钮 / 重发原请求 | 一次提交；第二次拒绝或显示已提交 |
| 计算期间关闭 UI、移出范围、断线、卸载设备 | 写盘前重新核对绑定；未提交即不变，已进入写盘则按账本恢复 |
| 原生导入未确认就关闭 UI / 移槽 | PENDING 隔离，不自动重复扣料或退款 |
| 原单元仍在原槽，且无已保存消费凭证 | 靠近上游执行 `/occampaign retry <上游UUID>` 明确重试 |
| 消费已保存、OC 尚未入料 | 上游 0 号“恢复已保存进料”查询凭证并入账；重放不再消费 |
| 原单元不在原槽且无凭证 | 保持隔离，停止本批；不要再投一件猜测补料 |
| 成品凭证丢弃 / 放箱子 / 重复复制 | 都只引用同一个产品；数量不增加、不变为 GT 配方物料 |
| 重启后查询两批 | 新批次状态、旧残余与旧封装可查；旧批次可再次 claim |

主机事务与真实 GT 注册物品的服务器合成玩家测试由自动验收覆盖；此手册保留给真人客户端的画面、字体、按钮、鼠标操作及重连体验。硬断电、多人并发长跑、完整生存原料取得仍未验收。

## 8. 回收试算在哪里

打开 [批次工场的回收页](campaign-lab.html#recovery)。它以本批真实母液组分做比例分流，水、酸、副产物也返回。滑块不会修改游戏。100% 回流的示例没有有限稳态；降低回流会增加 purge。游戏内回收入口暂不开放，避免将未知混合物灌入只支持限定组分的反应器。

网页显示的批次是冻结的验收快照，实时游戏库存以右键 UI 和 `/occampaign report` 为准。
