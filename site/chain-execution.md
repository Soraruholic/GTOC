## 2. 模型版本、库存与热量

世界 schema 为 `oc-unit-world-2.3`。已有偶联线保留 `va-coupling-extent-1`，新建使用 `va-coupling-extent-2`。旧基线的 0.931 mol C20 不被重算，新干燥基线为 0.88445 mol。旧乙酰化模型与既有存量继续保持。

三次交接分别为偶联分析机 → 后段加氢釜，后段 H/辅料 → 空乙酰化线，乙酰化分析机 → 后段重排釜。玩家身份、所有权、维度、机器绑定、距离、窗口、nonce、序列号和 revision 由服务端验证；客户端只发送操作意图。所有关联设备都必须存在并已加载。

H 过滤回收设为 98%，其余物料明确进入废流，余氢留在气体库存。这是过滤与理想组分切分合并的教学操作，不等同于真实过滤器的分离能力。乙酰化单酯流的显热 549.709876 J 在下游记录为冷却边界，沿用旧模型的教学热容定义。反应热与压力保持未建模，不能由这些数值推出真实冷负荷或安全工况。

## 3. 可重复的三案例结果

单位为 mol，乙酰化温度均为 303 K，时间为 3600 模型秒。数量来自本版 Java 完整串联测试。

| 案例 | 最终全反式晶体 | 晶体中指定单 Z | 解释 |
|---|---:|---:|---|
| 干燥 + 选择性加氢 | 0.2609166427 | 0.00072476845 | C16 竞争副产物 0.05；H₂ 消耗 0.85703205 |
| 干燥 + 过还原对照 | 0.1643596509 | 0.00045655459 | 原炔位完全氢化副产物增加，进入乙酰化的 H 减少 |
| 湿料 + 选择性加氢 | 0.2311211284 | 0.00064200313 | 水先消耗格氏试剂，后续目标物流减少 |

三者晶体池中全反式摩尔分数同为约 99.723%，因为当前使用固定的 80:20 生成分配与 90%/1% 晶体回收参数；这不意味着工况变化没有现实纯度影响。≥99% 是只覆盖两种登记异构体的游戏质量门，未覆盖全部现实杂质、残溶与药典要求。产品留在设备库存，尚无 GT 物品导出。

## 5. 原生供给缺口与准入条件

下表依据先前对同一 GTNH 版本导出的 [运行时审计](data/vitamin-a/runtime-feedstocks.json)。该审计确认注册项与配方，并未证明所有矿物生成、生存科技解锁与设备制作可达性。本轮没有重新声称做过完整原生供应实测。

| 原料或支线 | 当前证据 / 缺口 | 下一步可交付内容 |
|---|---|---|
| 丙酮 → β-紫罗兰酮 → C14 | 丙酮已有运行时供给配方；β-紫罗兰酮上游及 C14 制备未入游戏 | 先冻结一个可解释的供应路线，逐步加入中间体、净式、副产物与开发门槛 |
| 甲醛 / 丙酮 → MVK → C6 | `fluid.formaldehyde` 与丙酮有注册记录；MVK、叔烯炔醇重排及 C6 Z/E 供应尚未接通 | 先完成最短 C6 供应切片，显式区分叔醇、伯烯炔醇与 Z/E，不跳步生成 C6 |
| 乙炔 | `acetylene` 有运行时登记与供给证据 | 冻结选定配方、数量及电压，再接带质量声明的单一导入边界 |
| Mg / Br / EtMgBr | 含溴矿电解存在；矿物可达性与上游解锁未验收；格氏试剂制备未实现 | 逐个审计矿物与设备成本，或在明确游戏级替代路径下建资源消耗；不把低 EU/t 电解等同于低阶全链 |
| 乙酸酐 / 氯乙酸 | 登记名为 `molten.aceticanhydride` / `molten.chloroaceticacid` | 确认适用组成/单位换算；先做只消费一种纯物料的进料边界 |
| 溶剂与助剂 | 原生 `ether` 的确切结构还需核实；吡啶与二甲苯缺现成注册映射 | 禁止按名称直接把 ether 当乙醚；补独立供应或公开、可付成本的游戏替代 |
| H₂ / 催化剂体系 | 夹具中已有材料账，未连原生输入与回收 | 先做消耗与完整回收账，再处理支持体、活性和再生；现实制备参数另审 |

禁止无依据把 mB 当 mol。进料需要物质身份、温度/组成声明、密度或明确的游戏换算政策；真实数据缺失时必须显示假设与适用范围。OC 与 GT 的外部存档无法天然构成单文件事务，导入设计继续沿既定隔离/恢复协议执行。
